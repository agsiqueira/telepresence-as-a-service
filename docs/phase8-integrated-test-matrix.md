This is the authoritative manual inventory for the integrated Explorer, Teleporter, Administrator, Safety, authentication, and live-Journey prototype. “Structurally validated” means source ownership and markers were inspected; it does not mean an authenticated, assistive-technology, database, paired-role, or real-device test passed.

## Known integrated finding

**IA-01 — Explorer Home route is unresolved.** Phase 8 describes five Explorer primary destinations: Home, Discover, Requests, Journeys, and Account. The approved repository baseline has four: Discover (`/viewer`), Journeys, Requests, and Account. There is no separate Explorer Home route, and authenticated `/` redirects to `/viewer`. Adding a duplicate link, inventing a dashboard, or moving Discover would change route ownership and exceed Phase 8.1’s low-risk policy. Approval is required before Phase 8.2 changes this architecture.

## Classification summary

- **Structurally validated:** canonical route files, guards, endpoint ownership, privacy markers, role-specific `VideoRoom` call sites, loading/failure/retry markers, and responsive/accessibility source markers.
- **Automated:** Phase 7 validators, lifecycle/service structural suites, camera switching, polling, authorization, and production build listed in the Phase 8.1 report.
- **Blocked — authentication:** protected route rendering and persisted account/application states without legitimate sessions.
- **Blocked — paired role:** cross-role concurrency and state propagation requiring Explorer and Teleporter sessions.
- **Blocked — LiveKit/device:** actual media permissions, devices, tracks, chat transport, and reconnection.
- **Manual test required:** breakpoint visuals, keyboard completion, Screen reader behavior, localization resilience, and zoom/reflow.
